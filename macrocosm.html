Primary Goal

Predicting Galaxy Redshift from Astronomical Images

Estimate redshift (distance) directly from cheap imaging with machine learning

Background

Redshift z tells a galaxy's distance & recession velocity — the backbone of cosmology. The exact way to get it is spectroscopy: accurate but slow & expensive, only a few targets at a time.

Model Value

Imaging is cheap & everywhere — every object already has it. We learn to predict the expensive spectroscopic z from cheap photometry/images. Benchmark: σ_MAD < 0.01 (Pasquet 2019).

Primary Goal · Real Data

What the data actually looks like

Live pull from SDSS DR17 — galaxies spanning the redshift range we want to predict

ugriz image cutouts pulled via astroquery

Same physical objects, increasing z → smaller & redder. That trend is the signal the model learns. 64×64 stamps centered on each galaxy via WCS.

One galaxy, five filters → the model input

Every object is imaged in 5 bands (u g r i z). Stack them → X_img = (64, 64, 5). Brightness/shape shifts across bands encode redshift.

Primary Goal · Data Access

Pulling the data with astroquery

Two calls build the whole dataset: one SQL join for labels + features, one image fetch per object

1 · Tabular — SQL join PhotoObj × SpecObj

# spectroscopic z (label) + photometry (features)
SELECT TOP 100000
  p.objid, p.ra, p.dec,
  p.modelMag_u, p.modelMag_g, p.modelMag_r,
  p.modelMag_i, p.modelMag_z, p.petroR50_r,
  p.run, p.camcol, p.field,      # locate frames
  s.z AS redshift
FROM PhotoObj p
JOIN SpecObj s ON s.bestObjID = p.objID
WHERE s.class='GALAXY' AND s.zWarning=0
  AND p.clean=1
  AND s.z BETWEEN 0.02 AND 0.35

2 · Image — 64×64 ugriz cutout per galaxy

from astroquery.sdss import SDSS
from astropy.coordinates import SkyCoord
from astropy.nddata import Cutout2D
import astropy.units as u

tab = SDSS.query_sql(sql, data_release=17)

def cutout(ra, dec, band):
    pos = SkyCoord(ra, dec, unit='deg')
    hdu = SDSS.get_images(coordinates=pos, band=band,
            radius=8*u.arcsec, data_release=17)[0]
    w = WCS(hdu[0].header)
    return Cutout2D(hdu[0].data, pos,
                    (64,64), wcs=w).data

img = np.stack([cutout(ra,dec,b) for b in 'ugriz'], -1)

✅ Verified end-to-end on DR17 — sample of 200 galaxies (z 0.02–0.35) + cutouts already pulled. astroquery caches frames locally, so re-runs are free.

Primary Goal · Model

Initial model design

Tabular baseline first for a fast benchmark → CNN on images → fuse both into one regressor

Architecture — two branches, one redshift head

X_img (64,64,5) ──► [ Conv×4 → BN → GlobalAvgPool ] ──► img_feat (128) │ ▼ concat X_tab (13) ──────────► [ StandardScaler / BN ] ──────► [ Dense 64 → Dense 32 ] ──► ẑ (redshift)

Baseline → Main

Baseline: XGBoost on the 13 tabular features → z. Trains in seconds, sets the bar & wires the webapp early.

Main: small CNN on (64,64,5) arcsinh-stretched cutouts, then fuse image features + tabular into a dense head.

Training & metrics

Loss: Huber/MSE on z · Adam + early stopping · split 70/15/15.

Report σ_MAD, bias ⟨Δz⟩, outlier rate (|Δz|/(1+z)>0.05), and a z_pred vs z_spec scatter. Target σ_MAD < 0.01.

Guardrail: observed-frame inputs only — never feed absMag/kcorr (derived from z → leakage). Stretch images, augment with flips/rotations.
